## 2. 如何验证与发布

1. 进入对应目录，阅读 README 的环境、外部依赖和测试命令。
2. 本地解析和单元测试先行；需要真实生成、训练或 GPU 任务时另外确认资源与任务范围。
3. 联调配置、结果目录和端口独立设置，开发副本不复用线上 `.env`；共享已有权重时按只读资源使用。
4. 测试通过后，比较开发副本与根目录服务，制作相关文件需要一起更新的部署清单，标为“测试通过，待部署”。根目录继续保留最近一次确认的部署源码。
5. 获得批准后，先保存服务器原文件和配置，再按清单更新、重启对应服务并检查真实请求。通过后，将实际部署代码同步到根目录并记录部署结果，具体步骤见[部署记录](../docs/deployment_status.md)。

服务器现有独立测试与实验目录暂时保留，部分目录中的文件也被线上服务调用，见[外部依赖说明](../docs/external_dependencies.md)。历史文档说明当时情况，当前状态看本页、各开发 README 和部署记录。

从 75 同步开发代码时，按[代码同步说明](../docs/code_synchronization.md)将对应文件放入本目录；已经部署并检查通过的源码同步到根目录服务。

## 3. 维护规则

开发目录只提交源码、测试、无密钥样例和必要说明。权重、训练数据、环境、任务结果和对象存储资产继续在仓库外管理。保留阶段性代码来源和验证结果；完成上线后更新状态，避免同一项长期标为待部署。

## 2. 如何验证与发布

1. 进入对应目录，阅读 README 的环境、外部依赖和测试命令。
2. 本地解析和单元测试先行；需要真实生成、训练或 GPU 任务时另外确认资源与任务范围。
3. 联调配置、结果目录和端口独立设置，开发副本不复用线上 `.env`；共享已有权重时按只读资源使用。
4. 完成验收后，比较开发副本与根目录对应服务，把同一批相互依赖的改动成组更新，并同步测试与文档。
5. 更新 GitHub 的源码不等于服务器部署。部署前另保存当前生产目标文件和配置，按批准清单更新、重启对应服务并核验。

服务器现有影子与实验路径暂时保留，参见[部署状态](../docs/deployment_status.md)。开发副本中保留的历史文档按其日期阅读；当前状态以本页、各开发 README 和部署记录为准。

## 3. 维护规则

开发目录只提交源码、测试、无密钥样例和必要说明。权重、训练数据、环境、任务结果和对象存储资产继续在仓库外管理。保留阶段性代码来源和验证结果；完成上线后更新状态，避免同一项长期标为待部署。

# 无机新材料服务建设情况

## 一、当前现状

### 1. 服务定位

当前服务定位为**无机晶体新材料发现与初步筛选**：接收上游给出的元素体系、稳定性偏好及候选数量等约束，生成此前未在当前任务中给出的无机晶体候选，并依次完成结构合理性检查、初步热力学评估、排序和可追溯交付。

它不应承担以下任务：

- 商品牌号、成熟材料或打印耗材的资料检索与筛选；
- 有机聚合物、树脂、PCB 配方等材料的生成；
- 高熵合金配比优化或工艺参数寻优；
- 直接给出可替代 DFT 或实验的最终结论。

上述边界应与“现有材料筛选与计算”“合金配比优化”服务保持清晰分工，避免上游因历史上下文或模糊描述将任务错路由到新材料生成服务。

### 2. 当前技术链路

现有主链路为：

```text
上游约束
  → 约束解析与元素体系确认
  → MatterGen 条件生成无机晶体候选
  → pymatgen 结构准入检查
  → MatterSim 弛豫/能量评估 + Materials Project 同元素体系竞争相查询
  → 形成能、E_hull 初筛与排序
  → CIF、结构预览、评分卡、任务清单等可追溯交付物
```

当前接口包括：

- `POST /new-material/generate`：同步提交生成任务；
- `POST /new-material/constraints`：解析和确认生成约束；
- `WS /new-material/start`：面向上层编排和前端的流式任务入口；
- `GET /new-material/tasks/{taskid}`：读取任务结果。

运行环境分为服务环境与生成模型环境：服务主体使用 `ai4m-service-py310`；MatterGen 与 MatterSim 依赖位于独立的 `mattergen-py310` 环境。该划分能够避免模型依赖污染服务环境，但也意味着部署时需要同时维护模型路径、GPU 可用性及两个环境的兼容性。

### 3. 当前可表达的输入约束

服务当前能稳定处理的主要是：

| 约束类别 | 当前含义与边界 |
| --- | --- |
| 元素体系 | `target_formula`、`allowed_elements`、`excluded_elements` 可用于确定或限制元素集合。 |
| 稳定性偏好 | `E_hull` 阈值可作为 MatterGen 的条件生成引导；默认值为 `0.05 eV/atom`。 |
| 生成数量 | `max_candidates` 控制本次生成候选数。 |
| 验证目标 | `validation_targets` 可记录后续希望验证的性质，但目前不是已计算出的预测结果。 |

需要特别说明：`target_formula` 在当前版本中主要用于**提取元素体系**，并不等价于严格保证生成候选具有该精确化学计量比。若后续需要“指定化学式的晶体结构预测”，需要引入针对精确组成约束训练或微调的 CSP 模型，不能把现有能力描述为精确化学式生成。

### 4. 当前输出及热力学结论的含义

单个候选可输出 CIF、结构图片/GIF、GLB、结构校验信息及热力学评分信息。默认热力学路径为：MatterSim 给出候选能量，并结合 Materials Project 同元素体系的竞争相构建局部相图，得到形成能和 E_hull 的初筛结果。

因此当前形成能和 E_hull 的正确表述是：

> **MatterSim–Materials Project 混合初筛结果，用于候选排序和后续验证优先级判断，不是 DFT 最终结论。**

其可信度依赖于 MatterSim 模型适用范围、Materials Project 竞争相数据覆盖、元素体系解析正确性以及参考能量体系一致性。若要用于正式材料宣称或工程决策，仍应对优先候选进行统一设置下的 DFT 复核，并结合可合成性与实验验证判断。

### 5. 当前历史任务与产物规模

截至本次盘点，结果目录中保存了 73 个历史任务目录及相应生成清单。按生成清单统计：

| 项目 | 数量 | 说明 |
| --- | ---: | --- |
| 历史生成任务 | 73 | 仅表示本地留存任务，不等同于独立材料数量。 |
| 生成状态为 `ok` | 64 | 约 87.7%；任务输入和运行环境并不一致，不能直接作为线上 SLA。 |
| 生成失败 | 5 | 需要按模型加载、参数、GPU 与外部依赖分别归因。 |
| 生成不可用 | 4 | 多与运行条件、模型或依赖不可用有关。 |
| 已产生结构校验记录 | 65 | 其中 62 个通过基础结构准入、3 个未通过。 |
| 具有数值形成能与 E_hull 的校验记录 | 54 | 说明仍有一部分候选未获得完整热力学结果。 |
| 通过当前 E_hull 阈值的记录 | 12 | 仅占已有热力学评估记录约 22.2%，反映“生成”与“稳定候选筛出”是两件事。 |

结果目录还留存约 109 个 CIF、124 个 EXTXYZ、64 个 GIF、74 个 GLB、142 个 PNG、70 个压缩包以及任务 JSON/日志等文件。它们构成了回溯任务的基础，但其中可能包含重复候选、失败任务和历史错误输入，不能直接等同于已确认的新材料库。

### 6. 当前版本的关键风险

现有历史清单中可见：部分结构未通过校验或未达到 E_hull 阈值的候选，仍可能进入后续排序结果。这意味着当前“有排名”不应被前端或用户理解成“已推荐”。

在未收紧流程前，结果至少应明确分为：

1. **可进入后续验证**：结构有效、热力学结果完整，并满足当前阈值；
2. **条件候选**：结构有效但 E_hull 偏高、竞争相覆盖不足或仅具近似评估；
3. **不建议继续**：结构不通过、评估失败或明显不满足阈值；
4. **验证未完成**：尚未得到形成能/E_hull，不能参与稳定性排序。

## 二、已完成治理与下一阶段计划

### 1. 已完成：统一服务身份与路由边界

服务已在 `/roles`、服务描述、日志、进度事件和最终报告中统一为“无机新材料发现与初步验证”。主线已清理 PCB、Robot_Materials、耗材选型、成熟材料检索以及旧 MP/ALIGNN 执行链，避免把服务错误识别为现有材料筛选或有机材料优化模块。

当前路由边界为：商品牌号和已有材料性能比较进入成熟材料服务；高熵合金元素配比进入合金配比服务；本服务只承接“探索新的无机晶体候选”。没有显式元素体系时，可由上游可追溯结论或受限 LLM 归纳；仍无法形成可靠起点时，以流式文字请求补充信息，不进行无约束生成。

### 2. 已完成：建立严格、结构化的任务交接

上游可传递独立的结构化字段；同时，服务会保留既有完整 envelope 并过滤旧进度 JSON，防止为了兼容历史调用而丢失真正的上游结论。推荐字段最低限度包括：

- 目标应用与材料类别；
- 明确元素体系或经用户确认的化学式；
- 禁止元素；
- E_hull 偏好及阈值；
- 候选数量与后续验证重点。

对 FDM、PLA、PETG、PCB、PINN 等非化学式词语，以及有机/商品材料和合金配比请求，服务已在生成前拒绝或提示转交，而不是把文本片段误解析成元素组合。

### 3. 下一阶段：将结构与热力学检查改为真正的筛选门槛

排序池应仅包含满足最低准入条件的候选。结构无效、热力学计算失败、E_hull 缺失或明显超过阈值的候选应移入“淘汰/待补算”列表，不能与可验证候选混排。

输出时应同时给出：候选总数、结构通过数、完成热力学评估数、E_hull 达标数及各类淘汰原因。这样用户看到的是实际收敛过程，而不是单一排名列表。

### 4. 完善热力学初筛与证据链

- 为每个候选记录 MatterSim 模型版本、弛豫状态、Materials Project 查询条件、竞争相数量、计算时间与失败原因；
- 对 MP 查询增加重试、限流、缓存和超时后的可恢复状态，减少外部接口波动造成“待计算”；
- 对重点候选建立统一 DFT 复核队列；
- 评估是否接入经过一致化处理的参考相数据，逐步从临时 MP 查询走向可复现的本地/固定版本参考体系。

### 5. 提升生成约束与候选多样性

当前 MatterGen 条件生成可体现元素体系和稳定性偏好，但不保证精确化学计量比、特定晶系或可合成路线。下一步应：

- 增加组成、元素比例、空间群、原子数与禁配规则的显式约束；
- 对重复/近重复结构做去重，保证交付的是多样化候选；
- 对确需固定化学式的问题，评估专用 CSP 模型或基于目标体系的微调方案；
- 将可合成性、原料可得性、毒性、成本和应用工况作为后排序约束，而不是只看 E_hull。

### 6. 优化结果展示和多模态交付

首屏应直接展示“本轮筛出多少可进入验证的候选、Top 候选的化学式/结构/形成能/E_hull、排序依据和下一步建议”。详细 CIF、计算日志、结构 GIF、GLB 和全量评分卡应作为可展开的证据附件。

图片和 GLB 不宜因“服务产生了文件”而默认逐个展示；只有当结构、晶格特征或可视化确实帮助用户比较候选时再展示。对主要决策无帮助的素材应留作下载与审计附件，减少报告噪声。

### 7. 建立可量化的验证基准

本服务基于预训练生成模型和外部热力学初筛，并不存在类似配比回归模型的单一 R²。后续应建立以下指标：

- 任务生成成功率、结构有效率、完整热力学评估覆盖率；
- E_hull 阈值通过率与候选去重率；
- 对已知稳定/不稳定材料的回放命中率；
- MatterSim–MP 初筛与统一 DFT 复核的一致性；
- 实验可合成率和关键性能的实验验证命中率。

只有在固定测试集、固定参考相和统一 DFT/实验标准下，才能比较不同版本的实际改进效果。

## 三、当前主要困难

### 1. 自然语言需求与物理约束之间仍有断层

“耐高温”“固态电解质”“材料筛选”“FDM 打印”等描述不足以直接构成 MatterGen 的物理输入。当前最重要的前置条件是明确无机元素体系；否则服务只能猜测模板，容易偏离用户目标。

### 2. 历史上下文会污染元素体系提取

上游若把旧进度事件、其他团队输出或完整对话直接拼接，缩写、单位和模型名称可能被误读为化学元素。历史任务中已经出现过这类输入污染迹象，因此应把“结构化交接、历史 JSON 过滤、化学式校验”作为可靠性工作的第一优先级。

### 3. 条件生成不等于满足条件

E_hull 目前是生成引导，不是硬性保证。候选还可能因结构无效、弛豫失败、竞争相不完整或 E_hull 偏高而被淘汰。服务应强调“生成—筛选—复核”的三级过程，避免把候选结构包装为已发现、已稳定的新材料。

### 4. 热力学结果属于近似初筛

MatterSim 与 Materials Project 的组合能显著降低候选初筛成本，但并非统一 DFT 的替代方案；不同模型、参考能量、材料体系和竞争相覆盖都会影响形成能与 E_hull。重点候选仍需统一计算设置的 DFT 复核。

### 5. 外部依赖与计算资源会影响结果完整性

模型加载、GPU 显存、MatterSim 弛豫时间和 Materials Project 查询都可能成为任务瓶颈。当前有一部分历史候选没有完整热力学数值，说明服务需要具备可重试、可恢复、可解释的任务状态，而不是简单显示“待计算”。

### 6. 结构稳定不等于可制造、可应用

即使候选具有较低 E_hull，也还需要考虑合成路径、动力学稳定性、缺陷、相变、环境稳定性、成本、毒性以及目标工况下的关键性能。新材料服务应提供后续验证优先级，而不是跳过这些环节直接给出工程定型结论。

## 四、阶段性结论

当前服务已经具备“无机晶体条件生成 + 结构检查 + MatterSim/MP 热力学初筛 + 资产化交付”的基础闭环，并保存了可追溯的任务产物。下一阶段的重点不应只是增加生成数量，而应收紧输入边界和筛选门槛：确保元素体系正确、把无效候选排除在推荐池外、明确初筛证据等级，并用统一 DFT/实验结果建立可量化的版本基准。
